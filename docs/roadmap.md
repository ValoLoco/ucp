# Development roadmap

All milestones are **proposal** plans, not dates or commitments. See [STATUS.md](../STATUS.md).

## Docs foundation

Index, overview, glossary, and spec chapter map: see [README.md](README.md) and [../specs/README.md](../specs/README.md).

## Milestone 1: Establish the concept

Publish the thesis, corrections, glossary, evidence register ([docs/claims.md](claims.md)), and stakeholder questions. Exit criterion: readers can distinguish the proposed protocol from existing law and deployed technology.

## Milestone 2: Specify the smallest useful record

Review existing entity identifiers and credential standards. Define record serialization, signatures, authority changes, recovery, privacy, and verification behavior. Exit criterion: reviewed specification and reproducible test vectors.

## Milestone 3: Build a local demonstrator

Create and verify a fictional entity record. Demonstrate authorized updates, key rotation, revocation, recovery, and conflict detection. Add optional Bitcoin anchoring only after local verification works. Exit criterion: tests reproduce both successful and rejected changes. No real securities or customer funds.

## Milestone 4: Obtain external review

Invite corporate-law, arbitration, space-law, Bitcoin, security, and distributed-systems specialists. Publish objections and revisions. Exit criterion: documented reviews, unresolved risks, and an explicit pilot decision.

## Milestone 5: Consider a narrow pilot

Only after technical and legal review, test one useful workflow with willing participants under existing law. Expansion into ownership records, contracting, or payments requires separate requirements and approvals.

No jurisdictional commitments, fundraising targets, or space deployment dates are implied.
